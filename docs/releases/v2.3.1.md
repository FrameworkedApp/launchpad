# LaunchPad v2.3.1

## Stack filtering for scaffolded projects

LaunchPad v2.3.1 fixes agent stack filtering in `/lp-review` and `/lp-harden-plan` for projects created through `/lp-pick-stack` and `/lp-scaffold-stack`. Before, these commands could not read the stack names the scaffolding saved, so they fell back to the full review roster, including reviewers for stacks the project does not use.

## Fixed

- **Stack filtering works for scaffolded projects.** `/lp-scaffold-stack` saves the catalog's stack names, such as `hono`, `next` or `django`, in `.launchpad/config.yml`. The agent stack filter accepted only the stack ids that detection writes, so a config such as `stacks: [hono, generic]` raised `unknown stack id(s)` and both commands dispatched every reviewer. The filter now maps catalog names to stack ids first. A name that maps to no known stack still raises, and both commands keep their fallback banner.
- **The Python reviewer for Django and FastAPI projects.** `/lp-define` now chooses the reviewers in the generated `.launchpad/agents.yml` from the mapped stack ids, so projects scaffolded from the `django` or `fastapi` catalog entries get `lp-kieran-foad-python-reviewer`.

## Internal

- **One alias table.** The table that maps catalog names to stack ids moved to `lp_pick_stack/stack_aliases.py`. The scaffold decision, the bootstrap enrichers, `/lp-define` and the agent stack filter all read it, and tests fail if a stack name LaunchPad can save is not accepted by the filter. `SCAFFOLD_HANDSHAKE.md` section 10.v2.3.1 records the change; no on-disk schema changes.

## Release validation

- Python suite, TypeScript tests, typecheck, lint, Pyright, Ruff, the handshake lint including the schema gate, and the release freshness gate pass on the release branch.
- The plugin ships 43 commands, 16 skills and 39 agents, unchanged from v2.3.0, and the Codex router's command inventory lists all 43.
- The live Codex install check in the maintainer release process was not run for this release.

## Upgrading from v2.3.0

Marketplace installs follow the `stable` branch and receive this release on their next update.

No migration is needed: existing `config.yml` files work as written. A previously generated `agents.yml` is not rewritten; to add the Python reviewer to a project scaffolded from `django` or `fastapi`, add `lp-kieran-foad-python-reviewer` under `review_agents` or re-run `/lp-define` and let it overwrite `agents.yml`.
